## Standalone frontend deployed and verified

User imported `n8n/insurance_rag_frontend_webhook.json` into n8n and activated
it, then enabled GitHub Pages for the repo (both manual, outward-facing steps
deliberately left to the user rather than done automatically - see
2026-08-11's handoff). First load rendered the page correctly (CSS/layout
fine, confirming GitHub Pages itself was serving right) but every reply came
back as a blank chat bubble, not an error.

**Diagnosed from the blank-not-red distinction**: a red error bubble would
mean the `fetch` call itself failed (network/CORS); a blank bubble with no
error means the request succeeded but the response body didn't have the
shape `index.html` expected. Root cause: the Respond to Webhook node's
`respondWith: "allIncomingItems"` setting wraps the response in a JSON
array, so `index.html`'s `data.reply` read as `undefined` - which renders as
an empty string via `textContent`, not the literal word "undefined" (the
DOM's `textContent` setter treats `undefined` like `null`, coercing to `""`)
- explains exactly why it looked blank rather than showing an error or a
recognizable bad value.

**Fixed**: changed the node's "Respond With" option from "All Incoming
Items" to "First Incoming Item" directly in n8n's UI (`respondWith:
"firstIncomingItem"`) - took effect immediately on the already-active
workflow, no re-import needed. Fixed the same field in the repo's copy of
the workflow JSON so a future re-import starts correct.

**Full conversation verified after the fix**: age 31, cover ₹1Cr, concern
"replacing income for my family", term 30 (correctly rejected - "We don't
have premium data for a 30-year term matching your age/cover/concerns.
Available terms: 20, 25" - the live term-validation working exactly as
designed), term 25, payment option "regular" (correctly rejected too -
"Available options for this term: limited_ppt_10, limited_ppt_15,
limited_ppt_5, single"), "limited ppt 10", budget ₹20,000 - produced a real,
grounded recommendation (LIC's Yuva Credit Life / 877, ~₹14,305/yr, correct
pros/cons, correct disclaimer) with the candidates list rendering below the
narrative. Confirms the whole chain end-to-end: GitHub Pages -> CORS ->
n8n Webhook -> HTTP Request -> `/chat` -> eligibility/interpolation/
narrative generation -> Respond to Webhook -> back to the page.
