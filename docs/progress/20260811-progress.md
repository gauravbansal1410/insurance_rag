## 877 derived from 878's grid instead of a second full scrape

Rather than scraping 877's own 24+ points, implemented a new
`DERIVED_POLICIES` mechanism in `build_premium_lookup.py`:
`build_derived_age_term_grid()` takes an already-built sibling's
`age_term_grid`, calibrates a single scale factor against the target
policy's own real anchor points (877's 6 spot-check points, each of which
was deliberately chosen 2026-08-10 to land on an exact point already in
878's grid, so no interpolation was needed to compute the ratio), rescales
every point in the sibling's grid by that factor, then substitutes the real
anchor values back in verbatim at their own (age, term) - matching the
existing "scraped always overrides brochure" precedent already used
elsewhere in this build script. Every derived point is tagged
`"source": "derived_from_878"` in the built artifact, kept fully separate
from `"scraped"` points - auditable, not silently blended in as if it were
real data.

**Calibration result: scale factor 1.262, anchor ratios ranged 1.2416-1.2766**
- lands exactly on the 1.24-1.28x range already found in the 2026-08-10
shape-transfer comparison, since it's the same underlying data. `sa_scaling`
for 877 is built normally from 877's OWN independently-extracted rebate
table (confirmed against the raw PDF back on 2026-08-08's session 4) - only
the age x term axis is derived, since the SA-scaling formula was already
known to be policy-specific and was never a candidate for cross-policy
transfer.

**Verified the derivation is working correctly, not just running without
error**: all 6 real anchor points reproduce their exact original scraped
values through the live dispatch (e.g. age=18/term=20 -> 5150.0, matching
the 2026-08-10 scrape exactly) - confirming real data correctly overrides
the derived estimate at its own point. A genuinely derived point (age=25,
term=15, never scraped for 877) predicts 4416.91, and checking the implied
ratio against 878's own real value at that exact point (3500.0) gives
1.2620 - exactly the calibrated scale factor, confirming the derivation
math is internally consistent.

Full regression suite re-run: `premium_interpolation.py`'s hand-check suite
unchanged (876's `4700.0` case, 877/878's `limited_ppt_15` hand-checks which
use a different payment option than our lookup's `limited_ppt_10` scope and
correctly still fall through to the old linear path), `check_concern_tags_sync.py`
clean.
