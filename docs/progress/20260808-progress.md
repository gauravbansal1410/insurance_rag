one `premium_lookup.json`. Adding 859 was a new list entry (own reference SA, own
ground-truth CSV, no `age_bands`/`rebate_sa_type_key`/`rebate_premium_type_key` at
all since its rebate table has no age dimension), not a rewrite - confirms the
2026-08-05 generalization work (typed rebate tables, `compute_sa_adjustment()`
dispatch) was pointed in the right direction. `build_sa_scaling()` also generalized
to dispatch on the rebate table's own `type` directly (previously hardcoded to raise
on anything but `percent_of_tabular_premium`) - a `per_mille_of_sum_assured_rupees`
policy now builds with an empty `qa_check` per band (859 has no cross-SA ground
truth yet, all 52 scraped points are at the reference SA itself) rather than being
unbuildable.

**Generalized `query/validate_premium_lookup.py`** to take an optional `policy_id`
CLI arg (defaults to 876, so the existing bare invocation still works unchanged).

**Generalized `query/premium_interpolation.py`'s dispatch** - removed the
hardcoded `_PREMIUM_LOOKUP_SCOPE` constant entirely. Each `premium_lookup.json`
entry already carries its own `premium_payment_option`/`sum_assured_type`, so the
dispatch now just checks `policy_id in _premium_lookup_table` and compares the
profile against that entry's own stored scope - no separate scope constant to keep
in sync as more policies get added.
