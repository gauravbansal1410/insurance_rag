insurance_rag — ingestion walkthrough

What happens between uploading a policy PDF and it being queryable

The one-time, admin-triggered half of this project — turning two raw PDFs into structured JSON, a searchable vector index, and precomputed relevance scores. Runs once per policy, not per query — this is what chunking/ingest_policy.sh does end to end. Every input and output shown below is the literal, real value produced by actually running LIC's Saral Jeevan Bima (policy 859) through the live pipeline — nothing paraphrased.

python3 chunking/precompute_rerank_scores.py chunking/chunks_859.json

Process

For each of the 8 fixed concern tags (query/concern_tags.py), one live Voyage rerank call (rerank-2.5-lite) scores every candidate chunk against that tag's canonical phrase. Results are merged into chunking/precomputed_rerank_scores.json and checkpointed to disk after every tag, not just once at the end — confirmed necessary after a real ~1.5-hour job was silently killed mid-run once (docs/progress/20260731-progress.md). This is exactly what removes the need for a live rerank call at query time (step 4 of the query walkthrough).
