insurance_rag — query-time walkthrough

What happens between a user typing an answer and getting a ranked recommendation

A RAG system for Indian term life insurance: it ingests 7 LIC policy documents into structured JSON + a vector index, then walks a user through a short Q&A and returns 3 real, ranked, grounded recommendations — never an invented product, with a real interpolated premium estimate for each. Everything below is the second half: what happens on the backend for one query. Every input and output shown is the literal, real value produced by actually running this profile through the live code — nothing paraphrased.

Python function call (in-process) Hits a persistent server Live call to a third-party API
Running example, used at every step below age 31 ₹1,00,00,000 cover 30-year term regular premium concern: replacing income for my family budget ₹20,000/yr

Always-on, before any query ever arrives

Three separate processes run continuously on one Oracle Cloud VM. A query never starts any of these — it only ever talks to them.

n8n

Public webhook / chat-trigger entry point. Deliberately a thin relay only — it forwards the request to the Python service and returns whatever comes back, never re-implements any pipeline logic itself.

service/main.py

FastAPI app, systemd service. Loads all 7 policies' Layer 1/2 JSON and the precomputed rerank table into memory once at startup — a query never re-reads a file. Also holds each chat session's in-progress answers, in memory, keyed by session_id.

Qdrant

Vector database, bound to localhost only. Holds one collection of policy-document text chunks, embedded once at ingestion time — a query only ever searches it, never writes to it.

Input

The 3 survivors from step 3's output, plus the scores dict from step 4's output.

Process

Sorts by concern_match_count descending, then by relevance tier (any two scores within a 0.05 tolerance count as the same tier), then by premium_amount ascending as the final tiebreaker. All 3 here tie on concern_match_count (each 1) and land in the same tier — 0.50390625 / 0.5234375 / 0.5 span only 0.023, well inside 0.05 — so the sort reduces almost entirely to price.
